# Used Car Price Prediction

A regression pipeline that estimates the resale price of used cars from listing
attributes (year, mileage, brand, engine, etc.). Built as a portfolio project to
demonstrate end-to-end ML engineering: feature engineering, leakage-aware
preprocessing, stacked ensembling, and reproducible evaluation.

## Why this project

Dealers and marketplaces need a fast way to flag mis-priced listings — a car
listed well below a fair-market estimate is a buying signal; one listed well
above is friction for sellers. A model that predicts price from the listing
itself gives both sides a reference point. The deliverable here is a CLI
that trains on a CSV of historical listings and produces a serialised
predictor (`car_price_model.joblib`) plus an honest held-out test score.

### Pipeline

1. **Feature engineering** (deterministic, target-free): horsepower parsed from
   the `engine` string; `car_age` and a `depreciation_factor = exp(-0.15 × age)`;
   non-linear transforms (log, squared) on age, mileage, horsepower;
   `miles_per_year` and a `milage_vs_expected` ratio; binary indicators for
   fuel type, transmission, accident history, clean title.
2. **Train / test split** *(before any target-aware step)*.
3. **Outlier removal** by IQR on the **training** prices only; the same cutoff
   is then applied to the test set so the held-out set never informs it.
4. **Imputation** (numeric medians) fit on train, applied to both halves.
5. **Bayesian-smoothed target encoding** of categorical columns
   (brand, model, model_base, fuel_type, transmission) — fit on
   the **training fold only** via an sklearn `TransformerMixin`.
6. **Stacked ensemble**: LightGBM + XGBoost + CatBoost as base learners, with a
   LightGBM meta-learner over 5-fold CV out-of-fold predictions.
7. **Evaluation** on the held-out test set, reported on the original USD price
   scale (not the log scale).

## Honest note on the previous performance claim

The earlier version of this README claimed `R² ~ 0.93+`. That number was
generated by a pipeline that fit the target encoder on the entire dataset
**before** the train/test split — a textbook source of leakage. The current
pipeline fits all target-aware steps strictly on the training fold; numbers
reported below are produced this way.

Headline metric to look at: **R² on the held-out test set on the price scale**
(`r2_price` in the CLI output). The log-scale R² (`r2_log`) is reported as
well but it's the easier number to inflate, so the price-scale figure is the
honest one.

## Quickstart

```bash
git clone https://github.com/Gavand1969/Used-Cars-.git
cd Used-Cars-
pip install -r requirements.txt

# Run the test suite (no CSV needed — uses synthetic data)
pytest tests/ -v

# Train + evaluate on your own CSV
python used_car_price_prediction.py --data path/to/used_cars.csv
```

Expected output:

```
Loaded 12345 rows from path/to/used_cars.csv

Held-out test metrics (price scale, USD):
  R²   : 0.XXXX
  RMSE : $X,XXX
  MAE  : $X,XXX
  R² (log target): 0.XXXX

Saved model to car_price_model.joblib
```

### CLI flags

| Flag | Default | Meaning |
|---|---|---|
| `--data PATH` | required | CSV with a `price` column. |
| `--output PATH` | `car_price_model.joblib` | Where to write the fitted model. |
| `--test-size FLOAT` | `0.2` | Held-out fraction. |
| `--seed INT` | `42` | Train/test split seed. |
| `--no-log-transform` | off | Train against raw price instead of `log1p(price)`. |

## Expected CSV schema

| Column | Type | Notes |
|---|---|---|
| `price` | float | Target, in USD. |
| `model_year` | int | E.g. `2018`. |
| `milage` | int | Odometer (note the original-dataset spelling). |
| `brand` | str | Manufacturer. |
| `model` | str | Model name; first two tokens used as a `model_base`. |
| `engine` | str | Free text; horsepower is extracted from a leading `NNNHP`. |
| `fuel_type` | str | `Gasoline`, `Hybrid`, `Electric`, `Diesel`, ... |
| `transmission` | str | `Automatic`/`Manual`. |
| `accident` | str | `Yes`/`No`/`None reported`. |
| `clean_title` | str | `Yes`/`No`. |

Extra columns are ignored. `id`, `ext_col`, `int_col` are dropped if present.

## Predicting on new listings

```python
import joblib
import pandas as pd

model = joblib.load("car_price_model.joblib")

new_car = pd.DataFrame([{
    "model_year": 2020,
    "milage": 35_000,
    "brand": "Toyota",
    "model": "Camry",
    "engine": "203HP 2.5L 4 Cylinder",
    "fuel_type": "Gasoline",
    "transmission": "Automatic",
    "accident": "No",
    "clean_title": "Yes",
}])

print(f"Predicted price: ${model.predict(new_car)[0]:,.0f}")
```

Unseen brands or models fall back to the training-set global mean rather than
crashing.

## Reproducibility

- Splits, encoders, and base learners are seeded (default `42`).
- `requirements.txt` pins major versions.
- `pytest` runs end-to-end on a synthetic dataset, so CI doesn't need the real
  CSV. The synthetic data has a known linear-ish structure; the smoke test
  asserts the model clears R² > 0.5 on it.

## Limitations

- No time-based split. If listing dates were available, evaluating on a
  forward-in-time window would be a more honest test of how the model
  generalises to future market conditions.
- Hyperparameters are hand-tuned; no Optuna run is included to keep CI fast.
- The dataset itself isn't bundled — drop your own CSV in or point `--data` at
  the Kaggle "Used Car Prices" dataset (or similar).
